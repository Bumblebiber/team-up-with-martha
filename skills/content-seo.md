# Content strategy and SEO

Content earns attention that ads rent. Plan content that answers what the ICP
already searches for or discusses, and make it findable.

## Search intent first

For each topic, classify the intent before planning a piece:

| Intent | Query looks like | Content that wins |
|---|---|---|
| Informational | "how to X", "what is X" | Guide, tutorial, explainer |
| Commercial investigation | "best X", "X vs Y", "X alternative" | Comparison, honest alternatives page |
| Transactional | "X pricing", "download X" | Product, pricing, install page |
| Navigational | brand name | Homepage, docs |

Check the live results for the query (search it). Whatever format ranks —
listicle, tutorial, docs page — is what the search engine thinks the intent is.
Report what you saw and when.

## Keyword and topic research without paid tools

- Autocomplete, "People also ask", related searches.
- The words customers use in issues, forums and Reddit (voice of customer).
- Competitors' top pages: what they cover, what they miss.
- Prefer specific long-tail queries with clear intent over broad head terms a
  new site cannot rank for.
- Say plainly that volume estimates without a keyword tool are guesses.

## Content plan

Organise as topic clusters: one pillar page per core problem, supporting pieces
that link to it. For each piece: target query, intent, angle (what makes it
better than what ranks now — original data, working code, first-hand
experience), format, CTA, distribution channels.

Developer content that works: real tutorials with runnable code, honest
comparisons including where the product loses, postmortems and "how we built
X", benchmarks with published methodology.

## On-page checklist

- Title tag ≤ ~60 characters, query near the front; meta description
  ≤ ~155 characters, written as an ad for the click.
- One H1; H2/H3 mirror the questions the reader has.
- Answer the query early; depth after.
- Descriptive URL slug; internal links with descriptive anchor text.
- Images with alt text; code as text, not screenshots.
- Structured data where it applies (FAQ, HowTo, SoftwareApplication,
  Article).
- Technical basics: indexable, in the sitemap, fast, mobile-friendly,
  canonical set, no duplicate pages competing.

## Distribution

Publishing is half the job. For every piece list where it goes after
publication: newsletter, social posts (written per platform, not one post
cross-posted), relevant communities where allowed, README/docs links, outreach
to people who linked to similar content.

## Quality bar (E-E-A-T)

Show first-hand experience and expertise: real examples, real numbers with
sources, a named author. Thin rewritten content is not worth producing; say so
when that is all the input allows.
